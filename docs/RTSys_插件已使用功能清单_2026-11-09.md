# 当前插件使用的 RTSys 软件功能清单

**日期**：2026-11-09  
**对象**：`TrioAI_RTSys` 插件（`RTSysPlugInAdapter` / `RTSysPlugInNative` / `PlugInWorker`）  
**范围**：只列**当前代码实际调用或依赖**的 RTSys 能力；文末单列“已预留但尚未启用”的接口，避免与已落地功能混淆。  
**依据**：插件 C# 源码、`register_plugin.py`、`PlugInShimNative.cpp`，以及 `docs/ida_analysis/` 中已确认的宿主 ABI/偏移。

> **一句话总览**：插件以“停靠面板”形式运行在 `RTSys.exe` 进程内，借助宿主的插件框架、停靠窗口、主题色、Scintilla 编辑器、工程树内部模型和 `.zpj` 工程文件，把 AI 对话与工程编辑接到 RTSys 界面上；同时通过 `zmotion.dll` 独立连接控制器，完成程序、变量、IO、EtherCAT 等读写。

**状态说明**：✅ 已实际使用　⚠️ 可用但受限　⛔ 当前返回“不支持/占位”

## 一、宿主插件框架（RTSys.exe 外壳）

| # | RTSys 功能 | 插件中的用途 | 实现位置 | 状态 |
|---|-----------|-------------|---------|------|
| 1 | 插件注册表登记 | 在 `HKCU\Software\RTSys Application 1.0\RTSys\Plugin` 写入 `Count`、`PluginN`、`Menu nameN`、`Menu promptN`、`DirN`，让 RTSys 启动时在菜单里出现“AI 插件”。 | `register_plugin.py` | ✅ |
| 2 | `Plug_in` 目录与 DLL 加载 | RTSys 按 `安装目录\Plug_in\<DirN>\<PluginN>` 找到插件 DLL，用 `AfxLoadLibrary` 加载，并要求导出 `PlugIn_Create`。插件用原生 shim 承载 .NET 4.8 托管程序集。 | `register_plugin.py`、`PlugInShimNative.cpp` | ✅ |
| 3 | 六个插件生命周期导出 | `PlugIn_GetHandle`（交回宿主上下文）、`PlugIn_SetDockBar`（声明支持停靠栏）、`PlugIn_SetAutoSize`（声明支持自动尺寸）、`PlugIn_Create`（创建面板并返回 `CWnd*`）、`PlugIn_Reserved`（保留接口）、`PlugIn_Destroy`（释放资源）。 | `PlugInAbi.cs`、`PlugInNativeExports.cs` | ✅ |
| 4 | 停靠面板（DockBar） | `PlugIn_SetDockBar` 返回 `true`，宿主创建 `CPluginView` 并把指针传给 `PlugIn_Create`；插件从对象偏移 `+0x20` 读出真实 HWND，再用 WPF `HwndSource` 以 `WS_CHILD` 嵌入面板。 | `PlugInHostAdapter.cs` | ✅ |
| 5 | 宿主期望的 MFC `CWnd*` 返回值 | 宿主把 `PlugIn_Create` 的返回值当成 MFC `CWnd*`：`+0x00` 是 vptr、`+0x20` 是 `m_hWnd`。托管代码无法造原生 vtable，因此插件在可执行内存里分配“假 CWnd”块（vtable 槽位全部指向返回 FALSE 的 stub）。 | `PlugInHostAdapter.cs`（`FakeCWnd`） | ✅ |
| 6 | 自动尺寸 | `PlugIn_SetAutoSize` 返回 `true`；插件每 150 ms 轮询宿主父窗口的 `GetClientRect`，用 `SetWindowPos` 把嵌入子窗口同步到客户区大小。 | `PlugInHostAdapter.cs`（`StartSizeFollow` / `TickSizeFollow`） | ✅ |
| 7 | 面板关闭检测 | RTSys 关闭插件面板时通常只隐藏/销毁父窗口，不调用 `PlugIn_Destroy`；插件在尺寸跟随定时器里检测父窗口可见性/有效性变化，主动关闭自己打开的设置、历史、记忆、关于等对话框。 | `PlugInHostAdapter.cs` | ✅ |
| 8 | 重复 `PlugIn_Create` 处理 | RTSys 每次点击插件菜单都会重新调用 `Create`，但不先调用 `Destroy`；插件在重新挂载前清理旧的 `HwndSource`、尺寸定时器和假 CWnd 内存块，避免每次打开都泄漏一套资源。 | `PlugInHostAdapter.cs`（`DetachPreviousView`） | ✅ |
| 9 | 宿主主题色 | 通过 `ExtMainHmi.dll` 的导出 `?ZHMI_GetMainThemeColor@@YAHPAPAK00@Z` 读取背景色、前景色、强调色（COLORREF）；每约 6 秒轮询一次，颜色变化时重建插件 UI，使面板跟随 RTSys 深/浅主题。 | `PlugInHostAdapter.cs`（`TryGetHostThemeColors`） | ✅ |
| 10 | 宿主初始化/控制器信息消息 | ABI 中预留了 `WM_HOST_INITIALIZED = 0x52D`、`WM_HOST_CONTROLLER_INFO = 0xFB8` 及处理函数骨架，但当前没有实际挂钩窗口过程，消息处理逻辑为空。 | `PlugInAbi.cs`、`PlugInHostAdapter.cs` | ⚠️ 预留 |

## 八、当前明确未使用或不支持的功能

以下能力在代码里有入口或占位，但**当前不会真正执行**，列出来避免误判：

| 功能 | 现状 |
|------|------|
| HMI 内部对象模型（`ZHmi_FileClass` / `ZHmi_WindowClass` / `GetWinBmp` 等） | 仅存在于 IDA 分析文档，尚未接入插件；当前 HMI 功能只是 `.hmi` 文件只读解析。 |
| 轴实时状态、轴使能 | 状态结构未验证，返回空或异常；`ZMC_SetAxisEnable` 没有暴露给 AI 工具。 |
| 断点、进程列表、进程变量、事件日志、程序类型描述符、IEC 变量/IEC 任务 | 处理器直接返回“RTSys 不支持/未实现”。 |
| 系统变量（SysVar） | `sysvars` / `sysvar` 路由返回不支持，提示改用 VR/TABLE。 |
| EtherCAT 设备扫描、MSBus 扫描 | 返回不支持。 |
| 机器人、配方、远程设备、示波器 | 返回不支持或占位。 |
| `ZMC_Modbus_*`、`ZMC_Pause/Resume`、`ZMC_Execute/ExecuteNoAck`、`ZMC_DownMemZar`、`ZMC_Delete3File`、固件相关 `ZMC_*` | `ZMotionAPI.cs` 中有 P/Invoke 声明，也做了部分封装，但当前没有 AI 工具或 HTTP 路由调用它们。 |
| 插件自动打开/启动恢复 | 当前代码没有“启动后自动弹出插件面板”的逻辑；插件由用户在 RTSys 菜单点击后，宿主调用 `PlugIn_Create` 打开。 |

## 九、按“RTSys 软件功能域”归类的简表

| 功能域 | 插件是否使用 | 说明 |
|--------|-------------|------|
| 插件框架 / 菜单 / DockBar | ✅ | 注册、加载、停靠、自动尺寸、主题、生命周期。 |
| 主窗口 / 工程视图 / 编辑器 | ✅ | 标题解析、工程树内部模型、Scintilla 读写保存。 |
| 工程文件（`.zpj` / `.bas`） | ✅ | 清单解析、增删改复制、GBK 编码、本地缓存、备份。 |
| HMI（`.hmi` 文件） | ✅（只读） | 解析窗口/控件/文本；未使用宿主 HMI 对象模型。 |
| 控制器连接与状态 | ✅ | 自动搜索、静态 IP、仿真器、规格/版本/状态。 |
| 程序编译/下载/运行 | ⚠️ | 编译下载链路存在，但“从控制器读源码”不可用，实际受源码来源限制。 |
